# 第 5 章 一个向量，四种表达：双流程几何内核

> 作者：量子剑客
> 第二卷 · 架构：让复杂度各归其位

## 一、引言问题："所见即所交付"为什么这么难

造型部门的日常工作里有一个心照不宣的断层：评审会上看到的，和工程部门收到的，不是同一个东西。预览用的是三角网格，快、流畅、能实时旋转；交付要的是 NURBS 曲面，精确、可光顺、能进下游 CAD。连接两者的传统工序叫"逆向拟合"——从网格反推曲面。拟合必有残差，残差必有人工修补，修补必不复现：设计师在预览端改的每一条线，到了工程端都要重新"翻译"一遍，而翻译从来不对等。

断层的根源不在工具不够多，而在表达不同源。网格和曲面分别由两套数据驱动，各自演化，靠人工对齐。本章的核心命题是：**单一参数向量同时驱动网格、NURBS、质量与导出四种表达，消除二次拟合**。当四种表达都是同一个向量的纯函数，"所见即所交付"才从口号变成定理——预览里被认可的那个形状，与 STEP 文件里被交付的那个形状，由同一份参数生成，差异为零。

## 二、原则

**原则一：单一参数源，其他一切都是派生。** 系统里只允许一个可以被人编辑的对象——参数向量。网格、曲面、评分、导出文件全部从它派生，派生过程不允许携带自己的隐藏状态。凡是"在网格上直接拉一个点""在曲面侧手工补一块"的编辑入口，都是在制造第二个真相源。

**原则二：表达下游化，四种表达按需取用。** 不同环节需要不同的几何表达：交互要三角网格（快），工程要 NURBS（准），评审要质量指标（可判），交付要 STEP/IGES（可流通）。四种表达各有用途，但没有一种配称"主表达"——它们都是对同一参数向量的四种投影，用哪张投影取决于你此刻要回答什么问题。

**原则三：拒绝二次拟合，正路一条走到底。** 从参数正向生成曲面，而不是从网格反向拟合曲面。正向生成没有拟合残差，设计师的每次编辑精确传播为控制点的改变；反向拟合永远带着一个不可消除的近似误差，且误差随编辑次数累积。二次拟合省下的，是一次性的开发成本；付出的，是每一次迭代的不确定性。

**原则四：公差前置，判据内生于构造。** 质量标准不是构造完成后的检验工序，而是构造过程的组成部分：连续性阈值、采样密度、分级口径在生成的同时被固定。事后检验发现的问题只能返工，构造时内生的判据才能预防问题。

## 三、案例解剖：双流程如何共享一个向量

EVOLUTION AI 的整车由 22 维 CarParams（`algorithm_model/car_modeling/car_params.py`）描述，这一个对象是两条几何路径的共同输入。

**网格路径服务交互。** 参数化车身由纵向与环向截面环构建（默认离散 48×24），经组件装配器与车轮、车灯、格栅、后视镜、玻璃等部件合装，输出 10 部件、176 顶点、316 面的整车网格，供给 Three.js 视口实时预览与 STL/GLB 镶嵌化导出。装配器同时报告各部件的顶点/面数、包围盒与稳定部件色，让前端能渲染、能识别、能统计。

**NURBS 路径服务工程。** 独立的构建器从控制网格出发，将车身构建为真正的 NURBS 曲面（整车 33 片），专用模块构建与车身之间具有 G1 切线过渡的前后端盖。配套自由曲面算子含扫掠与倒角；STEP 由纯 Python 写出器（`algorithm_model/freeform/step_writer.py`）按 ISO 10303-21 输出，不依赖 Open-CASCADE 量级的重型内核。关键之处在于：曲面由参数直接生成，而非从三角网格反拟合——不存在拟合残差。

**质量与导出是同源的下游。** 连续性检查器（`continuity_checker.py`）对具名曲面的四条参数域边界逐条采样（默认每边 50 点），以 G0 0.1 mm、G1 1.0° 为阈值逐缝判定，输出 TXT/CSV 报告；曲面质量包在网格侧给出 G0/G1/G2 计数、反射线评分与 A–D 等级。两条路径、两种粒度的判据互补：接缝处的精确 NURBS 连续性，加上镶嵌化车身上的曲率分布。

链路因此闭合为：`CarParams ──► mesh 装配 ──► 交互预览 / STL / GLB`，`CarParams ──► NURBS 车身 + G1 端盖 ──► G0/G1/G2 分析 ──► STEP/IGES`。每一个箭头都是同一参数向量的纯函数。这正是第 3 章的贝叶斯优化器能把"造型 + 质量"整体视为单一可求值函数的原因——建议一组参数，四种表达同时就位，没有任何表示需要手工重建。

## 四、反模式与代价

**二次拟合补桥。** 预览用网格，交付前再逆向拟合 NURBS。代价是拟合残差加人工修补：每次设计迭代都要重付一遍翻译费，且修补结果不可复现——"上次是怎么修过来的"没有答案。

**双源真相。** 参数面板改一套，网格侧再手工拉一套。短期看是灵活，长期看是灾难：两版形状谁也算不清差在哪，评审认可的版本与工程收到的版本之间隔着一条人工对账的鸿沟。

**预览与交付两套几何。** 为了流畅，预览用简化模型；为了交付，另建精细模型。代价是"所见非所得"被制度化：评审通过的从来不是将要制造的东西。

**公差事后检验。** 几何先随便建，质量等交付前再验。代价是问题只能返工不能预防；且临近交付的返工没有时间预算，最终以质量妥协收场。

## 五、操作清单

| 检查项 | 通过标准 | 本仓库证据（文件或命令） |
|---|---|---|
| 参数是唯一可编辑对象 | 无绕过参数直接改几何的入口 | 22 维 CarParams 为唯一入口，`algorithm_model/car_modeling/car_params.py` |
| 四种表达同源 | 网格/NURBS/质量/导出均由参数正向生成 | 网格 176 顶点装配（`body.py` + 装配器）；NURBS 33 片（`body_nurbs.py`） |
| 无二次拟合路径 | 代码库中不存在 mesh→NURBS 反拟合工序 | 双路径均自 CarParams 出发，见 `docs/EVOLUTION_AI_paper.md` 第 4 章 |
| 公差内生 | 连续性阈值在构造期固定并逐缝判定 | G0 0.1 mm / G1 1.0°，每边 50 采样点，`continuity_checker.py` 输出 TXT/CSV |
| 导出可独立验证 | STEP 输出可在第三方内核中打开检查 | 纯 Python `step_writer.py`（ISO 10303-21）+ 附 FreeCAD 验证宏 |
| 闭环一轮可复现 | 参数 → 四种表达 → 评分一条命令走完 | `python algorithm_model/test_all.py` 五模块自检 |
