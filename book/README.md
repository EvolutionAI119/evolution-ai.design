## 一、这本书是什么

这不是一本讲"如何调用 AI 写代码"的工具书，而是一套 **AI 原生（AI-native）软件开发的完整方法论**：
从认识论（什么是 AI 原生系统）、架构论（如何让 AI 与人共同承担复杂度）、工程论（如何把不确定性收敛为可验证的交付），
到组织论（总体设计部与研讨厅）与演化论（快变量与序参量）。

全书以 **EVOLUTION AI 汽车造型平台** 作为贯穿案例。它不是修辞性的举例，而是每一章都可核对的实证基线：

| 事实 | 数值 |
|---|---|
| 后端路由模块 | 19 |
| HTTP 端点 | 154（152 路由 + 2 系统） |
| ORM 数据表 | 17 |
| 前端页面 | 12 |
| 自动化测试 | 1000+（算法 200 / 后端 411（408+1skip+2xfail）/ 前端 416，2026-10-25 实测） |
| 核心算法规格 | 22 维 CarParams、176 顶点、33 曲面、G0/G1/G2 |
| 优化引擎 | RBF-GP（ℓ=0.25）、EI/UCB、14 维造型空间、0.01 收敛阈值 |

案例只提供"证据"，方法论提供"可迁移的规则"。读者可以不复刻这个平台，但应能复刻这套方法。

## 二、读者对象

- **技术负责人 / 架构师**：需要为 AI 参与的研发体系定架构、定边界、定验收。
- **AI 工程与算法工程师**：需要把模型能力接入生产系统，而不是停在 notebook。
- **产品与项目负责人**：需要判断"AI 能做几分、人该做几分"，并让承诺可验证。
- **研究者与学生**：需要一套从复杂巨系统到工程落地的完整链路。

## 五、写作与维护规格（供后续增补章节遵循）

1. **篇幅**：中文每章 1800–2600 字，英文对应 1200–1800 words；附录可更长。
2. **结构**：每章固定六段——引言问题 → 原则（2–4 条）→ 案例解剖（本平台实证）→ 反模式与代价 → 操作清单 → 本章自检（3 问）。
3. **图表**：每章 1–2 张图，直接引用仓库已有 SVG（`../docs/images/<name>.svg`，英文版用 `../docs/images/en/<name>.svg`），并配中文图注；不新造插图。
4. **数据**：所有数字必须与 `docs/ARCHITECTURE_DESIGN.md`、`docs/VALIDATION_REPORT_20261025.md` 一致（19 / 154 / 17 / 12 / 1000+，2026-10-25 实测）。
5. **术语**：首次出现给中英对照；全文统一（见附录 A）。
6. **双语**：`zh/` 与 `en/` 同名同序，论点、案例、数字、图表一一对应，不做删节。
7. **引用**：引用本仓库文档时用相对链接 `../docs/<file>.md`；外部文献列入附录 D。
