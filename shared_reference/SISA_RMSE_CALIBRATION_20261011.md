## 二、需要澄清的口径：`evalTopRMSE` 量的是「车与车的形态差」，不是「建模精度」

上游文档 §3.3 已自行注明「两台不同车的客观形状差距」——**这个判断是准确的**。
本回执补充**量化证据**，供决定该指标能否用作回归阈值。

### 2.1 关键事实

参考包来自**一台真实车**（SUV 形态）。把**任意另一台车**的顶廓线与之比较，
其 RMSE 的**下限**取决于两台车的形态差异，而非任何建模质量。

### 2.2 实测（SISA 侧 6 个车型预设，归一化 x 100 点，与平台同口径）

| 车型 | 定位 | 对参考车 RMSE |
|---|---|---|
| 墨玉 S | 入门 | 0.2107 |
| 墨玉 L | 行政长轴 | 0.2068 |
| 墨玉 G | 旗舰 | 0.2032 |
| 墨玉 R | 运动 | 0.2035 |
| 墨玉 X | 跨界 | 0.2007 |
| 墨玉 T | 旅行 | 0.2112 |

**6 个形态各异的车型全部落在 0.20–0.21**，与上游记录的 Cayenne ≈ 0.217 **同一量级**。
这正说明该数值主要由「与参考车像不像」决定，而**对车型差异不敏感**。

### 2.3 推论（供判断）

- 若把 `evalTopRMSE` 当**回归阈值**：任何正常车型改动都会在 0.20 附近波动，
  阈值定高则失效、定低则误报，**无法区分「建模变差」与「换了个车型」**。
- 它**依然有用**，但用途应是：
  1. **跨车型对比**——同一参考车下，哪个车型形态更接近真车；
  2. **同车型变更前后对比**——比较**同一车型**改动前后的差值（ΔRMSE），
     这才是真正的回归信号；
  3. **接入 NURBS 顶线后**（上游 §5 预留），用它衡量「NURBS 生成顶线
     相对参数化近似顶线**是否更接近真车**」。

### 2.4 若要「建模精度」，正确的口径是**留出验证（hold-out）**

SISA 侧的做法：拟合用训练截面，评估用**未参与拟合**的留出截面，
得留出 CV 0.9956（≈ 拟合残差 2σ 内）。这与「对另一台车的 RMSE」是**两个不同的量**，
不可互相替代。

**建议**：文档与 UI 文案避免把 0.217 表述为「像真度/精度」，
可改为「**与参考车形态差异（越低越接近该参考车）**」。
如需要，SISA 可另交付一份**留出验证口径**的说明，供平台做自身的精度回归。

## 三、参考包更新流程（回应上游 §5 维护指南）

上游 §5 写明「SISA 交付新 JSON 后，用提取脚本重新生成 `src/config/sisaReference.js`」——
流程正确。SISA 侧对应入口（已入库）：

```bash
python -m sisa.reference_pack --deliver-to <平台工作区>
# 产出 shared_reference/SISA_REVERSE_REFERENCE_PACK.json
#      shared_reference/README_SISA_REFERENCE.md
```

当前包内含：`reference_curves`（200 点 × x/z/y_half）、`landmarks`（15 项）、
`coordinate_system`（含 `toPlatformX` 映射所需 L）、`quality`（fit RMSE 中位 10.235mm）、
`sections`（24 截面 × 80 点，**上游 §3.3-4 已预留但尚未使用**）。
