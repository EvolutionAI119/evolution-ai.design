## 执行摘要

EVOLUTION-AI.DESIGN 在约 68 天内从一个工程骨架演进为一套「参数化汽车造型 + A 级曲面算法 + 反重力飞行」的设计平台，主线可归纳为五条：

1. **后端与算法基座**（09-27）：认证、LLM 代理、训练后端、CAD 导入、贝叶斯寻优、G0/G1/G2 曲面判据。
2. **平台工程化与合规化**（09-29 → 10-11）：RBAC、社区、通知、影响证据、PostgreSQL/Docker、CSP、SEO、CNAME、京东云部署清单。
3. **账号体系整体封存 → 全站游客模式**（10-11）：这是一次**明确的需求转向**，微信登录、Account、Admin 全部退出公开前端。
4. **2D/3D 造型单一真源重构**（10-07 → 10-25，最长也最密集的一条线）：NURBS 连续车身 → 比例语义统一 → 座舱玻璃拓扑纯函数化 → 轮拱包络/轮腔装配 → 车门与侧窗联动 → bevel 与门洞几何收尾。
5. **能力扩张与文档沉淀并行**（10-16 反重力飞行、10-22 品牌 DNA、10-23 → 10-25 五图原则/双语论文/方法论图书）。

截至 2026-10-25，主线停在 `b42e51e4`，已通过 gh-pages 发布 `9fd5f04a`，公网产物 MD5 与本地构建逐字节一致（见「当前状态」）。**唯一未关闭的问题**是用户反馈的「打开车门后依然有东西遮挡」——几何层面的遮挡物已定位并修复，剩余观感问题（外摆门板本体 + 无内饰的空腔）仍在待裁决状态。

### 5.7 bevel 尺寸与门洞遮挡收尾（10-24 → 10-25，本次会话）

用户先后两次以截图/口述指出同一类问题，构成两轮修复：

**第一轮 ——「多余车身重复面和误拓扑联接导致的折痕」（`353e68ce`）**

| 缺陷 | 根因 | 修法 |
| --- | --- | --- |
| 车顶「白色重复面」 | `bevelSize = 0.03` 让车顶周边内收出 25mm 台阶，视觉上像叠了一层板 | `BODY_BEVEL_SIZE` 0.03 → **0.012** |
| 整车比设定宽 60mm | `depth = W` 时，bevel 在 Z 两端各扩 `bevelThickness` | `bodyDepth = W − 2×bevel`，`bodyExtentZ = W/2` |
| 前后轮拱折痕 | `archNotch` 底部 90° 凹角的 bevel miter 自交折叠 | 凹角加 12mm 圆角（`Q` 二次贝塞尔），切线连续 |

验证：`vitest` 15 文件 / **416 测试**全通过；多机位截图；公网 MD5 与本地 `dist` 逐字节一致；退化三角形从 28 个（轮拱角点）降至仅剩前后保险杠极端角点（不可见）。

**第二轮 ——「打开车门后依然有东西遮挡」（`b42e51e4`）**

这一轮暴露了第一轮留下的**真实回归**，也纠正了此前多次误判：

| 缺陷 | 根因 | 修法 |
| --- | --- | --- |
| 门缝装饰条开门后悬在门洞中央 | `addSeam` 造的 6 根缝条挂在车身上（非铰链），开门后不退场 | 收入 `doorSeams`，`s.visible = doorProgress < 0.02` |
| 车门/门缝/把手/后视镜/轮毂整体浮出车身 12mm | `deriveWheelFitment` 仍用旧式 `W/2 + bevel`，而真实半宽已被改成 `W/2` | 改为接收真实半宽 `bodyHalfZ`，`Car3D` 传 `bodyExtentZ` |

**方法论上的关键教训（已写入记忆）**：

1. **`Page.navigate` 到同一 URL（含 hash）不会重载 SPA**，页面状态（`visible`、材质）跨脚本残留，导致「门洞无遮挡」的假阴性结论。正确做法是先 `about:blank` 再导航。
2. **后台标签页 `requestAnimationFrame` 被节流**，开门动画不推进（`rotY` 停在 0.02），必须 `Page.bringToFront`。
3. **A/B 隔离是判断「有无多余几何」的唯一可靠手段**：隐藏全部车门后门洞干净通透，才敢判定「洞是通的」。
4. **本轮最终实测**（公网）：门洞中心沿 Z 轴射线 **0 命中**（完全贯穿）；剩余覆盖物只有绕前铰链外摆约 70°（`rotY = 1.222`，默认 `door_open_angle = 70`）的门板本体，以及随门旋转的门玻璃。

## 验证与交付纪律（方法论沉淀）

- **单一真源**：任何几何量只允许有一个计算入口（`LINE_RATIOS`、`WHEEL_ENVELOPE`、`ROOF_FILLETS`、`BODY_BEVEL_SIZE`、`shellHalfZAt`）。
- **测试门槛**：前端 15 文件 / 416 测试；早前 10-11 记录为「341 + 142 回归」；后端 SISA 曾达 773 passed 零回归。
- **多机位视觉验证**：侧视 / 等距 / 保险杠 45° / 斜视近景，任一机位发现异常即回归。
- **发布闭环**：`npx vitest run` → `npm run build` → 复制 `dist` 到纯 ASCII 路径的 gh-pages worktree（`D:\ghp-deploy-tmp`）→ 推送 → **公网 `Get-FileHash -Algorithm MD5` 与本地逐字节比对**。
- **发布传播窗口**：推送后 `index.html` 会先行更新，而**新 hash 资产在数分钟内仍可能返回 404**（10-25 实测：同一 URL 稍后重试即 200）。因此校验必须重试到「index.html 引用的 chunk 全部可取」为止，404 不等于产物缺失。
- **推送前专利守卫**：`pre-push` 钩子扫描未推送提交，命中专利特征即阻断；`EVOAI_ALLOW_PUSH=1` 仅作临时逃生门。
- **已知工具陷阱**：dev server（5173）的 HMR/ES module 强缓存会让浏览器 agent 命中旧代码——复验一律用**生产构建 + 新端口 preview**。
