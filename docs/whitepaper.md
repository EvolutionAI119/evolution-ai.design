## 1. 执行摘要

EVOLUTION AI 是面向汽车 A 级曲面开发的 AI 造型平台，以「**从一句话到 3D 整车**」为产品主张，把传统手绘驱动的造型流程重构为参数驱动的工程化流程：

```
概念参数 → 参数化建模 → AI 优化 → 质量分析 → 工程交付
```

平台当前规模（v1.2，全部数字锚定源码）：

| 维度 | 规模 |
|---|---|
| 前端 | Vue 3 + Vite + Three.js；10 个页面，Hash 路由 + 全局登录守卫 |
| 后端 | FastAPI + Pydantic v2 + SQLAlchemy 2.0；16 个路由模块 / 118 个 HTTP 端点 |
| 数据 | SQLite；11 张 ORM 表（含 Fernet 加密的 API Key 存储） |
| 算法 | 5 个算法包：参数化整车、NURBS 自由曲面内核、曲面质量评估、分镜生成与展示 |
| 测试基线 | 489+ 自动化用例（算法 200 / 后端 178 / 前端 111）+ 一站式五模块自检 |

平台的三条工程立场：

1. **信号优先，绝不模拟（Signal, never simulate）**——依赖缺失时显式报告不可用，而非返回编造的指标。
2. **薄壳编排，不重写算法**——Web 层只做编排与持久化，几何与智能能力沉淀在可独立安装的算法包。
3. **全链路可审计**——参数、样本、评分、变体、训练任务均可追溯、可回滚。

## 2. 行业背景与问题定义

### 2.1 传统造型流程的结构性瓶颈

| 环节 | 传统方式 | 瓶颈 |
|---|---|---|
| 概念表达 | 手绘效果图 | 主观创意难以量化、难以复用 |
| 曲面构造 | 工程师依据线条逆向建模 | 设计意图在转译中损耗 |
| 质量校验 | 人工逐面检查 | 周期长、标准依赖个人经验 |
| 方案迭代 | 周级往返 | 方案数量受限于人力 |
| 数据沉淀 | 散落在个人文件 | 组织知识无法积累 |

### 2.2 电动智能化带来的新要求

- 造型硬点改变（无前舱硬约束、轴距占比提升），参数空间需要重新定义；
- 软件定义汽车要求造型数据与工程数据在同一数字流中协同；
- AI 能力（生成模型、视觉语义、LLM 专家）必须被**可靠地**纳入工程流程，而非停留在演示。

### 2.3 EVOLUTION AI 的回答

以**参数空间**统一设计意图与工程硬点，以**贝叶斯优化**实现数据高效的自动寻优，以**NURBS 精确几何**保证工程可交付，以**异构 AI 融合层**（视觉模型 + 深度学习 + LLM）扩展创造力边界，并以 Web 平台把五者编排为一个闭环。

### 3.3 四条端到端业务流

1. **参数化概念设计**：参数输入 → 3D 整车 → 云端批次/评估/生成/优化 → 变体保存；
2. **CAD 导入改参导出**：文件上传 → 参数解析 → 改参预览 → 多格式下载；
3. **质量驱动迭代**：质量检查 → 报告/历史 → 回到设计端调整；
4. **ML 训练闭环**：创建训练任务 → 轮询指标 → 样本经贝叶斯容器产出。

## 4. 核心能力体系

### 4.1 参数化整车建模

- **22 维 CarParams**：主尺寸（L/W/H/wheelbase）、区段长度（hood/cabin/trunk/front_overhang/rear_overhang）、离地间隙、造型参数（roof_arc/windshield_rake/rear_glass_angle/waist_line/fender_prominence/wheel_arch_bulge）、玻璃深度、车轮（radius/width/spoke_count）、车灯（width/height）；
- 参数带**边界校验**（如 L ∈ [3.5, 6.0] m），越界显式报错；
- 截面式车身：沿车长取 48 个截面生成连续壳体，`process` 开关控制是否保留构造顺序；
- 整车装配输出 10 个独立部件网格，可单独操作或合并导出 GLB。

### 4.2 NURBS 自由曲面内核（freeform）

- 自研轻量内核：NURBS 曲线/曲面基函数、节点矢量、扫掠曲面、圆角曲面、混接曲面；
- **不依赖重型 CAD 内核**即可写出工程级 STEP（`step_writer.py`），并提供 NURBS 车身 STEP 导出；
- 连续性检查器以 0.1 mm 位置公差 / 1.0° 角度公差逐对输出偏差报告（TXT/CSV），支持端部 4 种连续性方案（共享边界、G1 连接、附着端等）。

### 4.3 曲面质量评估与优化

- **G0/G1/G2 分级**：G1 阈值 5°、G2 阈值 2°；
- **反射线评分**：曲率均匀度 × 0.5 + 平滑度 × 0.5；
- **综合等级**：A（G2>85% 且反射线>0.7）/ B（G2>70% 且反射线>0.5）/ C（G2>50%）/ D；
- **模拟退火光顺**：法向跳变平方和为目标，Metropolis 接受准则，指数降温；适用于硬点冻结后的局部光顺。

### 4.4 贝叶斯优化寻优

- **14 维造型参数空间**，RBF 核高斯过程（Cholesky 求解）+ EI/UCB 双采集函数；
- 观测数 < 2 时随机空间填充，之后切换 GP 驱动；
- 会话全生命周期：创建 → suggest → observe → best → samples；
- **样本桥接**：观测可导出为与 `/ai/train` 兼容的训练格式，使真实优化数据逐步替代合成样本。

### 4.5 深度学习与 LLM 融合

| 能力 | 实现 | 降级策略 |
|---|---|---|
| 造型参数分类/回归 | 后台线程 PyTorch 训练 | 无 PyTorch 时显式报不可用 |
| 纹理语义分析 | CLIP 六维度评分 | 无权重时回退几何特征并标注 |
| NURBS 专家对话 | 本地 Ollama / LLM 接口 | 无 Key 时显式客户端错误 |
| 多模型统一代理 | 7 个 LLM 提供商，Key 经 Fernet 加密 | 逐服务商状态可见 |

### 4.6 知识表达资产

- **分镜系统**：3 套内置模板（car_promotion / tech_demo / minimal_showcase），时长等比缩放，渲染为 Markdown/HTML；
- **设计元理论**：Love 九层框架与十维度自主知识体系（见 [design_meta_theory.md](design_meta_theory.md)）；
- **方法论与设计哲学**：见 [methodology.md](methodology.md)、[design_philosophy.md](design_philosophy.md)。

## 5. 技术架构

### 5.1 五层架构

| 层 | 内容 |
|---|---|
| L1 前端 | Vue 3 + Vite + Three.js + Element Plus + Pinia；10 页面，双语 i18n，全局守卫 |
| L2 接入 | Vite 开发代理 / Nginx；`/api/v1` → FastAPI:8000；公网经 cpolar HTTPS 隧道 |
| L3 后端 | FastAPI 0.104 + Pydantic v2；16 薄壳路由模块 / 118 端点 |
| L4 算法 | algorithm_model 独立可安装包：car_modeling / freeform / surface_quality / storyboard |
| L5 基础设施 | SQLite + 文件存储；可选 Redis（缺失时降级进程内会话）；后台训练线程 |

### 5.2 数据模型（11 张 ORM 表）

`projects`、`model_files`、`workflows`、`workflow_steps`、`quality_reports`、`parameter_sets`、`model_variants`、`users`、`api_keys`（Fernet 加密）、`parameter_records`、`training_tasks`。

### 5.3 认证与安全

- JWT（登录/微信），全局路由守卫；
- 训练与 API Key 管理端点强制认证，LLM 代理为可选认证；
- API Key 以 Fernet 对称加密落库；生产环境 `SECRET_KEY` 缺失时 fail-fast。

详见 [ARCHITECTURE_DESIGN.md](ARCHITECTURE_DESIGN.md) 与 [api_reference.md](api_reference.md)。

## 7. 质量与可信度基线

| 层 | 框架 | 用例 | 范围 |
|---|---|---:|---|
| 算法 | pytest | 200 | NURBS 数学、扫掠/圆角、构造器、质量、SOP |
| 后端 | pytest | 178 | 路由、模式、优化服务、安全、持久化 |

| 自检 | test_all.py | 5 模块 | 一站式端到端健全性门禁 |

**可信降级契约**：无 PyTorch → 训练显式失败；无 LLM Key → 显式客户端错误；无 CLIP 权重 → 几何特征兜底并标注；无 Redis → 进程内会话。所有路径遵循「信号优先」。

最新验证记录见 [VALIDATION_REPORT_20260927.md](VALIDATION_REPORT_20260927.md)。

## 8. 边界与演进路线

### 8.1 当前边界（诚实声明）

- 22 维显式参数可解释但无法表达任意自由手势与局部雕刻；
- 各向同性 RBF GP + 随机池采集优化偏简单，面向更高维空间需要各向异性/学习型长度尺度；
- QLoRA 式组织项目史微调尚未交付；
- 制造约束、干涉、空气动力学目标仅部分建模——目标函数设计是比优化数学本身更主要的领域挑战。

### 8.2 演进方向

1. **参数化升级**：草图/学习条件控制层，NURBGen 式生成基元；
2. **代理模型升级**：多保真度建模（廉价网格曲率 + 昂贵精确 NURBS 评估）；
3. **数据闭环**：真实贝叶斯战役持续替换合成样本，并支撑可审计的微调；
4. **知识体系化**：设计元理论 → 造型语言范式 → 组织级知识资产。

## 9. 结语

EVOLUTION AI 证明了现代 A 级曲面开发的关键技术——精确 NURBS 几何、数据高效的贝叶斯优化、视觉语言语义与大模型——能够被组合为一个可信的 Web 平台，而非彼此孤立的工具。参数驱动的双几何管线、GP+EI/UCB 优化器与训练数据桥接、以及真实降级的异构 AI 融合层，共同缩短了从概念比例到工程 STEP 输出的闭环，并使每一个结果保持可编辑、可审计。
